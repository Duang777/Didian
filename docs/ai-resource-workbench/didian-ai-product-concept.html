Recommended Direction

让浏览器和云盘之间出现一个会工作的 AI 资源处理层

Didian 不把 AI 放在云盘文件后的聊天框里，而是在资料进入云盘前完成理解、去重、命名、证据整理、产物生成和确认写入。

Mission Workspace

每个 Mission 都是一组 Markdown 文件。Agent 在文档里工作，用户在文档里审阅，Atlas 以后也从这个工作区重新打开上下文。

  • mission.md目标和任务边界
  • sources/browser-use.md来源摘要
  • evidence.md证据和引用
  • decisions.mdReview 记录
  • outputs/项目对比表.md确认后生成

整理 AI Agent 生态资料到云盘

目标是把当前标签组里的 AI Agent 项目资料整理成一个可复用资源包。Codex 需要保留来源引用，避免重复保存，并在写入 Mock Drive 前等待用户确认。

项目 主要价值 Didian 复用点
browser-use 自然语言浏览器自动化 标签页理解和页面动作模型
Stagehand 可靠的浏览器操作抽象 可解释操作和证据边界
OpenCode 本地 CLI Agent 工作流 Runtime 执行和日志回传体验

产品能力拆解

每个阶段都能单独演示，但组合起来才是 Didian 的差异化：保存前理解，本地执行，确认后入库，完成后召回。

Capture

第一版采集标签页、选区和备注；后续接入收藏、搜索结果、下载完成、RSS 和云盘新增文件。

01
Mission

第一版由 Codex 整理资料包；后续支持多 Runtime 接力、Workspace 模板和垂直任务流。

02
Review

第一版确认安全写入；后续扩展到版本变更、证据冲突、许可证风险和 dry-run 自动化。

03
Atlas

第一版沉淀资源合集；后续做跨应用召回、过期提醒、主题演化和跨合集比较。

04

安全边界

Didian 的自动化必须可解释。MVP 只允许安全写入，不做删除、覆盖和批量移动。

可确认

可确认

禁止

破坏性操作

删除、覆盖、批量移动不进入 MVP，未来也必须经过更强确认。
